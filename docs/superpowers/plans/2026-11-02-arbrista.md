# Arbrista Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Arbrista, a self-hosted PWA where every occupant of a household tracks plant watering through daily, de-duplicated watering sessions.

**Architecture:** One TypeScript repo. A pure `domain/` (dates, rhythms, seasons, due dates, sessions); `application/` use cases talking to ports; `infrastructure/` adapters (node:sqlite, filesystem, web-push); a thin Hono `server/` with a one-minute reminder scheduler; a Svelte 5 PWA in `web/`. The server runs TypeScript directly through Node's built-in type stripping (no server build step).

**Tech Stack:** Node 22 (type stripping, `node:sqlite`), TypeScript (strict, `erasableSyntaxOnly`), Hono + `@hono/node-server`, valibot, web-push, Svelte 5 + Vite + vite-plugin-pwa, qrcode, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-02-suivi-arrosage-design.md`

## Global Constraints

- Node.js 22, ESM, TypeScript strict; relative imports carry the `.ts` extension; only erasable syntax (no `enum`, no parameter properties, no namespaces).
- `domain/` imports nothing outside `domain/`, never reads the system clock, does no I/O.
- `application/` imports only `domain/`, `shared/` and `node:crypto`.
- Dates: `LocalDate` = `"YYYY-MM-DD"` in the household time zone; instants are ISO-8601 UTC strings.
- Weekday numbering: `0` = Monday … `6` = Sunday.
- Defaults: `sessionTime` `"18:00"`, `timezone` `"Europe/Paris"`, `summerStart` `"04-01"`, `winterStart` `"10-01"`.
- Env: `PORT` (3000), `DATA_DIR` (`./data`), `VAPID_SUBJECT` (`mailto:admin@localhost`). `DATA_DIR` holds `arbrista.db`, `photos/`, `vapid.json`.
- Photos: ≤ 5 MB, `image/jpeg` | `image/png` | `image/webp`; client resize: longest side 1600 px, JPEG quality 0.8.
- Notification: title `🌿 Session d'arrosage`, body `N plante(s) à arroser aujourd'hui` (`1 plante à arroser aujourd'hui` / `3 plantes à arroser aujourd'hui`), url `/`.
- UI copy in French; touch targets ≥ 44 px; light/dark via `prefers-color-scheme`.
- Errors: `ValidationError` → 400, `NotFoundError` → 404, `UnauthorizedError` → 401, others → 500 with body `{ "error": "Erreur interne" }`. Error body shape: `{ "error": string }`.
- Commit after every task; messages in English, conventional style.

## Review Focus

1. **Time zones / DST** — a watering at 00:30 Paris time belongs to that Paris day, and an 18:00 session fires at 18:00 Paris time on both sides of a DST change. Pinned in Task 1 (`toLocalDate`/`toLocalTime` DST tests).
2. **Editing a plant's rhythm** — changing the rhythm re-anchors “every N weeks” on today; editing only the name must not shift the schedule. Pinned in Task 6.
3. **Deleting a plant** — its photo files are removed from disk storage, not only DB rows. Pinned in Task 7.
4. **Southern-hemisphere / inverted season bounds** (`summerStart` after `winterStart`) — season computation wraps around the year. Pinned in Task 2.
5. **Removed occupant** — their token stops working (401) but their past waterings still show their name. Pinned in Task 5 and Task 8.

### Task 2: Rhythms and seasons

**Files:**
- Create: `src/domain/rhythm.ts`, `src/domain/season.ts`
- Test: `tests/domain/rhythm.test.ts`, `tests/domain/season.test.ts`

**Interfaces:**
- Consumes: Task 1 calendar, errors.
- Produces (`rhythm.ts`):
  - `type WeeklyRhythm = { kind: 'weekly'; days: Weekday[]; everyWeeks: number; anchor: LocalDate }`
  - `type IntervalRhythm = { kind: 'interval'; everyDays: number }`
  - `type Rhythm = WeeklyRhythm | IntervalRhythm`
  - `validateRhythm(r: Rhythm): Rhythm` — throws `ValidationError` unless: weekly days non-empty, unique, each 0–6, `everyWeeks` integer 1–52, `anchor` valid; interval `everyDays` integer 1–365. Returns the rhythm with `days` sorted.
  - `isScheduledOn(r: Rhythm, date: LocalDate, lastWatered: LocalDate): boolean` — weekly: weekday of `date` ∈ days AND `(diffDays(startOfWeek(date), startOfWeek(anchor)) / 7) mod everyWeeks === 0` (use a non-negative modulo); interval: `diffDays(date, lastWatered) >= everyDays`.
- Produces (`season.ts`):
  - `type Season = 'summer' | 'winter'`; `type SeasonBounds = { summerStart: MonthDay; winterStart: MonthDay }`; `type PlantRhythms = { summer: Rhythm; winter: Rhythm | null }`
  - `seasonOf(date: LocalDate, bounds: SeasonBounds): Season` — summer iff month-day ∈ `[summerStart, winterStart[`, cyclic.
  - `rhythmOn(rhythms: PlantRhythms, date: LocalDate, bounds: SeasonBounds): Rhythm`
  - `validateSeasonBounds(b: SeasonBounds): SeasonBounds` — both valid `MM-DD` (month 1–12, day valid for a leap year), and different; else `ValidationError`.

### Task 3: Next due date and overdue (R1, R2)

**Files:**
- Create: `src/domain/schedule.ts`
- Test: `tests/domain/schedule.test.ts`

**Interfaces:**
- Consumes: `rhythmOn`, `isScheduledOn`, `addDays`, `diffDays`.
- Produces: `nextDueDate(rhythms: PlantRhythms, lastWatered: LocalDate | null, today: LocalDate, bounds: SeasonBounds): LocalDate` and `daysOverdue(due: LocalDate, today: LocalDate): number` (`max(0, diffDays(today, due))`).

Algorithm: `lastWatered === null` → `today`. Otherwise iterate `d = lastWatered + 1 …` and return the first `d` with `isScheduledOn(rhythmOn(rhythms, d, bounds), d, lastWatered)`. Bound the loop at `366 * 53` iterations, then throw `Error('No due date found')`.

```ts

const monThu = { kind: 'weekly', days: [0, 3], everyWeeks: 1, anchor: '2026-11-02' } as const
const every = (n: number) => ({ kind: 'interval', everyDays: n }) as const

  expect(nextDueDate({ summer: every(5), winter: null }, null, '2026-11-02', north)).toBe('2026-11-02'))

  expect(nextDueDate({ summer: monThu, winter: null }, '2026-11-02', '2026-11-02', north)).toBe('2026-11-05')

})

  const r = { kind: 'weekly', days: [5], everyWeeks: 2, anchor: '2026-11-02' } as const
  expect(nextDueDate({ summer: r, winter: null }, '2026-11-07', '2026-11-07', north)).toBe('2026-11-21')

it('interval: N days after last watering', () =>
  expect(nextDueDate({ summer: every(5), winter: null }, '2026-11-02', '2026-11-02', north)).toBe('2026-11-07'))
it('overdue does not accumulate: one late watering resets the schedule', () => {

  const due = nextDueDate(rh, '2026-11-02', '2026-11-10', north)
  expect(due).toBe('2026-11-05')
  expect(daysOverdue(due, '2026-11-10')).toBe(5)
  expect(nextDueDate(rh, '2026-11-10', '2026-11-10', north)).toBe('2026-11-12')
})
it('switches to the winter rhythm when the candidate date is in winter', () =>
  expect(nextDueDate({ summer: every(5), winter: every(12) }, '2026-09-28', '2026-09-28', north)).toBe('2026-10-10'))
it('switches back to the summer rhythm in spring', () =>
  expect(nextDueDate({ summer: every(5), winter: every(12) }, '2027-03-25', '2027-03-25', north)).toBe('2027-04-01'))
it('without winter rhythm, summer applies all year', () =>
  expect(nextDueDate({ summer: every(5), winter: null }, '2026-09-28', '2026-09-28', north)).toBe('2026-10-03'))
```
